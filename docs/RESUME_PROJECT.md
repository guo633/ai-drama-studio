## 面试高频追问 · 应答要点

**Q：为什么拆五步，不一次生成？**
单次生成上下文任务过重，产出结构混乱且设定前后矛盾。拆步后每步只解决一个问题，且上一步产出作为下一步约束，错误不会向下游扩散；这是链式生成的标准做法（类似 LangChain Sequential Chain 思想，本项目为轻量手写实现）。

**Q：Prompt 模板为什么放数据库而不是写死在代码里？**
对应 Skill 的核心思想：把领域经验做成可复用、可迭代、无需改代码即可改进的资产。模板支持 {变量} 插值，用 format_map + 缺失变量兜底，单变量缺失不会崩整条流水线。

**Q：生成耗时长，怎么保证体验和可靠性？**
体验：BackgroundTasks 异步执行 + 前端 2 秒轮询，进度条精确到步骤。
可靠性：每步完成即 commit（中断不丢已完成步骤）；异常统一捕获，任务置 failed 并把错误信息落库，前端可见失败原因。

**Q：AI 工具怎么用的？举个 AI 出错的例子。**
见 docs/AI_DEV_CASE.md —— 典型案例：AI 生成的代码用 db.get(PromptTemplate, key) 按 step 字段查询，但 db.get 只接受主键，端到端测试时流水线直接报错；定位后改为 filter_by 查询并补回空值校验。结论：AI 产出必须经接口级回归验证。

**Q：演示模式是什么，为什么这么设计？**
llm.chat 在未配置 API Key 时返回确定性演示文案，流水线照常推进。目的：面试 Demo 零成本、随时可演示；同时把 LLM 调用收敛在一个函数内，配置即切换真实模型，零代码改动。
